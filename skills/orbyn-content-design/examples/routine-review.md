# Synthetic morning review

This is an authored example, not an observed run or a tested notification service.
A routine is authorized to read three permitted sources and save a private brief.
It may continue those steps without another prompt; publication is outside its grant.

1. Two sources load; the third denies access. The worker exits. Show **Partial —
   Brief ready; one source unavailable**, link the brief and missing source, and
   offer to correct access or retry the missing part. If the job failed, its run
   detail also says Failed; it does not upgrade the goal to Completed.
2. A later attempt submits the private save, but its response is lost. Show
   **Outcome unknown — checking whether the brief saved**. Retrieve the matching
   operation result before retrying. A new phrasing is not a new write identity.
3. Another routine checks for updates and finds none. Keep its successful check
   in run history without adding a new interruptive card every hour. A new access
   failure is material and remains visible; muting alerts does not remove review.
4. Group the same unresolved source decision across repeated events, using its
   actual identity. Keep a separate team's permission request separate. Clicking
   the grouped item opens the current decision, not a stale prior attempt.
5. **Pause routine** stops new scheduled admissions under its actual contract.
   **Stop this run** reports request versus confirmed stop and retained effects.
   **Revoke source access** removes that grant, without claiming remote rollback.
   **Mute alerts** changes attention only. Each remains independently understandable.

Checks to select for an implementation: matching run/artifact/version, partial
result, late old event, accepted-but-lost response, new failure after quiet success,
muted-but-durable decision, and pause while a job is active. Inspect the resulting
review flow as relevant. No universal backend schema, upstream runtime adoption,
external messages, repeated stage approvals or full UI sweep is implied.
