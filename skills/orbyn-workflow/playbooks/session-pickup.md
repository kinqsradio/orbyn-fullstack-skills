# Resume existing work

Read the current handoff, request and actual git/process state. Recover the next unfinished step and preserve file ownership. Reuse valid evidence. Do not restart the project, clone old plans uncritically or create a new chat to resume the current task.

Use the parent [workflow](../SKILL.md) and repository scope. For a moved checkout,
stale session cwd or changed/failed runtime, apply setup's conditional
[continuation readiness](../../orbyn-setup/SKILL.md#resume-after-a-workspace-or-runtime-change).
Verify the next command's supported installed runner and distinguish actual
checkout from saved host binding; explicit workdir success is not a rebind.
Current matching readiness/check evidence remains reusable.

Use the [task record](../references/task-record.md) when existing notes do not
identify the candidate, checked behavior and next step. Reconcile the record with
current files before reusing it; avoid a second tracker for the same work.
For a substantive continuation, its [versioned form](../references/handoffs.md)
can be checked against the current revision and retained dirty snapshot. Resolve
changed ownership, user steering and failed/unrun checks before continuing.

For an autonomous program, reconcile every active unit, already-landed PR, dirty patch, remote head and owned process before selecting the next unfinished item under [autonomous delivery](autonomous-run.md). A prior summary cannot overwrite newer source or reopen a frozen no-merge handoff.

Use the worktree owner's [reuse/replacement decision](../../orbyn-worktree/SKILL.md#reuse-before-cloning-or-replacing)
before making another checkout. Verify the existing task/PR branch and correct
base/dependency, including later local work; stale cwd is not a missing clone.
Reconcile its [closeout hold](../../orbyn-worktree/references/task-closeout.md)
in the same record instead of restarting completed or frozen work.
