# Maintain the shared library

Use for local-versus-shared ownership questions, public contract changes, a full
sweep, attribution through rewrites, a shared edit before release, or an owner
consolidation.

## Consumer and local skills

Follow the [company/repository skill boundary](../../orbyn-setup/references/project-skills.md).
Inspect existing local skills and preserve credits/assets. Setup does not move,
namespace, register or synchronize target guidance. Creating a local skill is
separate authorized project work; do not invent a shared registration or migration
helper. Keep it out of the shared catalog, public manifest and upstream lock.

For a durable project check of a critical behavioral property, use the
[project verification method](project-verification.md). Keep its models, coverage
record and rerun instructions with the target owner, outside the shared catalog.
A generic prototype request does not require a new skill.

## Offline source text

Keep essential instructions and required references usable from disk under the
[offline contract](../../orbyn-setup/references/offline.md). Bundle licensed, pinned
source text when it is needed; keep attribution/update URLs and source hashes.
For sources without redistribution permission, author the needed explanation
independently and label the remaining evidence limits.

## Public contract

Treat the shared library as an upstream dependency of consuming projects. Keep
private product policy and source outside public contributions. A useful skill
change alters a decision or supplies a reusable artifact, not just vocabulary.
Check expected and adjacent routing cases, then reconcile the catalog and library
release through the documented contribution path.

When current work demonstrates a meaningful reusable gap, use the
[contribution feedback policy](contribution-feedback.md). Prepare a concrete,
sanitized proposal and offer it once at a natural checkpoint. The user can approve a
public PR, request a local draft or decline. Existing exact-scope authority carries
through. Publish only on explicit approval; silence and local improvement permission
are not approval. Keep company-only lessons local and continue the main task.

## Upstream comparison

For external skill freshness and source comparisons, use
[upstream review](../../orbyn-upstream-review/SKILL.md). Keep downloaded research in
ignored `orbyn-references/`, preserve existing local references and adopt selected
improvements into the owning skill. Keep our adaptations rather than replacing them
with an upstream collection, and leave an import pin unchanged after a review-only
change.

## Audit completeness without inflating the catalog

For a full sweep, inventory every catalog entry and its local support files.
Record its input, useful result, failure boundary, execution owner and actual
evidence; distinguish a focused principle from a complete workflow. Essential
execution must work from the local method rather than a link to a missing skill.
Add concrete operational guidance where a short summary loses the method, and
retain concise entrypoints when their linked resources supply it.

Keep only canonical entrypoints named `SKILL.md`. Bundled upstream entrypoint
text uses `SOURCE.md`, retaining original `source_path`, bytes, hashes and notices
in the snapshot record. Treat historical mentions inside that text as source data,
not as installed skills or permission to fetch them. Validate recursive discovery,
related catalog owners, local files and Markdown heading fragments.

## Attribution through rewrites

Maintained Orbyn guidance can be independently written while earlier derived
material retains its provenance. Keep attribution through new wording, a renamed
title or added length, and do not assert exclusive origin. Describe original
additions and retained lineage separately. A full audit counts as complete
qualification only when optional adapters and live behavior are verified; report
any that remain unverified.

## Shared edits and release

Before a shared edit, inspect library main, relevant open PR heads/bases and owned
local diffs. Reuse one canonical authoring candidate and coordinate shared writes.
Follow the [release handoff](../../orbyn-upstream-review/references/release-handoff.md).
An unmerged candidate is not released main. Targets use the same outer source;
there is no copied installation or consumer pin promotion.

## Consolidate an owner

When consolidating an owner, migrate incoming links, presets, examples, active
cases and host discovery together. Preserve old measured suites/revisions as
historical evidence. A declared catalog retirement maps an old reading-group
selection to the maintained owner; remove only known owned discovery links,
preflight both hosts and retain foreign/company content. Preserve incorporated
source/license records when moving a derived reference into an original skill.
