# Interaction lessons

Read this when a brief calls for a familiar product category. Each line keeps an interaction worth borrowing, in generic words. Build it for the user's own product or a fictional one, with its own name, marks and look. A category is free to use; a real company's identity is not.

| Product category | Interaction to borrow |
| --- | --- |
| Design canvas | Select an object, edit it in a properties panel, a colleague's second cursor arriving |
| Issue tracker | A command menu opened from the keyboard, then assigning an issue without leaving context |
| Team chat | A message arriving, a reaction landing on it, a reply opening its thread |
| Launcher | Keyboard search and clipboard history over a blurred desktop |
| File manager | Preview over a file list; a file dragged into a folder; the same window in frosted glass |
| Media player | A dark library with cover art and transport controls |
| Block editor | A slash command opening a menu of blocks; a comment and its reply on selected text |
| Mail | Row hover actions, archive with the gap closing, an undo toast |
| Calendar | Drag across a day to create an event, then a quick-create popup |
| Slides | Editing one slide while the thumbnail rail follows |
| Spreadsheet | Selecting a range, a sum formula, a chart responding |
| Web article | Search suggestions opening under a browser search field |
| Phone conversation | Composer, delivery feedback and a message arriving in a native-looking thread |

Look at any example at its intended width before borrowing from it. A recognizable interaction can still have a weak crop, reset or transition, so give it the same rehearsal as a new scene.
