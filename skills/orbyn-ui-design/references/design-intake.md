# Pin the design and active surface

Use for a supplied design/reference or ambiguous multi-page UI control. First
identify the actual candidate and positive app/page marker, account/fixture and
surface. Port or tab order alone is insufficient. After navigation or structural
actions, obtain fresh structure/snapshot and resolve handles again; stale DOM
handles or old coordinates do not prove the next action's identity. Reuse supported
browser/project tools and avoid probe-only production dependencies or bypassing
capture restrictions.

For Figma, resolve the supplied file/branch/node and retrieve relevant context plus
reference screenshot through the available authorized source. Split large contexts
by actual child nodes if needed, preserving parent layout constraints. A supplied
local image needs no Figma account/tool or mandatory node question. Missing access
leaves Figma-specific extraction unverified; it does not justify guessing metadata.

Map relevant nodes to existing primitives, sizes to semantic tokens, and exported
assets/icons to actual files/exports. For example, a 40px reference action might
map to the consumer's existing medium Button; record a local justified size override
if no equivalent exists. Do not change global defaults, paste generated styling,
invent a logo/icon export or shrink text to hide overflow. Retain original asset
license and reference identity. Keep this mapping inline for a small change; a
complex screen can use an existing design note. Compare the matched content,
theme and state under [visual parity](../../orbyn-workflow/playbooks/visual-parity.md).
