## Gaps found and repaired

1. **Patch path injection:** an allowlisted filename containing newlines could
   inject extra unified-diff headers. Applying the generated patch created a file
   outside the selected owner. The helper now rejects ambiguous path characters
   before reading/exporting a file; ordinary selected patches still apply.
2. **Expiry during lock wait:** recall sampled time before acquiring its transaction
   lock and could return an entry that expired while waiting. Eligibility now uses
   time after lock acquisition and is refreshed before facets/snippets are returned.
3. **Malformed recall receipts:** wrong shapes could raise an internal attribute
   error or accept boolean values as integer generations/revisions. Receipt fields
   and numeric types are now validated explicitly.
4. **UUID operation IDs:** a normal lowercase UUID starting with a digit was rejected
   by the record-ID grammar. A separate operation-ID contract now accepts it and
   preserves exact-payload retry checks. Setup guidance also distinguishes an
   existing initialized store from a new empty root.

Lead-generated reproductions ran against both the frozen initial snapshot and
corrected code. The expiry and patch-header probes failed initially and passed
after correction. Four selected regression methods fail against the initial
implementation; malformed-input subtests produce multiple failure/error events,
so their event count is not the number of distinct methods. All new regressions
pass on the corrected implementation. Original negative receipts are retained.

Corrections from those findings:

1. **Transformed imports:** a valid future-dated input could become invalid after
   local timestamp replacement and poison later store operations. All final
   transformed records are now validated before any insert, and the shared save
   boundary validates final state. Mixed invalid imports roll back atomically.
2. **Existing alias merges:** source aliases are resolved before selecting affected
   records, and earlier aliases redirect to the new canonical tag. Empty/stale
   selections and already-canonical merges reject without mutation.
3. **Malformed lesson briefs:** non-string skill owners return a structured error
   rather than an unhandled type error.
4. **Revision bounds:** oversized revisions reject before reaching SQLite. A signed
   integer slot is reserved for the final forgetting receipt.
5. **Dependency cleanup headroom:** accepted records reserve one revision increment
   per outgoing relation. Near-limit dependents therefore cannot block another
   record's forgetting; cleanup removes relations and advances revisions without
   reuse or skipped cleanup. Automatic survivor timestamps also tolerate local
   clock rollback.
