## Change

The existing investigation owner now chooses existing local tools for bounded
artifact questions, then hands a specific missing observation to a compatible
REA engine when available and authorized. One maintained owner covers both
paths; no extra discoverable skill or runtime is installed.

The new local method covers format/digest identity, bounded inventory and source
slices, hidden bundle entries, safe selected archive reads, native metadata,
consistent read-only database snapshots and resource/evidence retention. A local
CLI observation is distinct from engine-issued Evidence and retained dossiers.
Different target bytes or incompatible schemas block the deeper comparison while
preserving the original local facts. Engine, runtime, installation and network
authority remain separate.

The four REA maintenance owners use the same handoff contract for performance,
tool design, CI and release scope. Descriptions, related routing, generated index,
provenance and distribution manifest are reconciled. Existing copyright/license
notices and source/runtime pins are preserved. New guidance is authored as Orbyn
methods; no external skill body, runtime or command collection is bundled.

The initial controller phase added three development definitions for hidden-package
inspection, static native metadata and local-to-engine identity/schema
