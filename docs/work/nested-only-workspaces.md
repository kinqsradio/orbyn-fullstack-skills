# Nested-only engineering workspaces

The copied-skill installer, selected host registration, company-skill relocation
and consumer pin/pull/export contract are retired. One outer library owns shared
policy, methods, source notices and discovery. Targets remain independent ignored
repositories with their own instructions/skills. See [setup](../installation.md).

## Migration and evidence

The replacement helper prepares only library repo/ and checks selected nested Git
roots, common metadata, ignore boundaries, revisions, dirty state and instruction/
skill metadata. No target files, excludes, models or discovery links change.
Existing external checkouts and active processes require coordinated preservation
before relocation. A retained recovery path is reported separately from a completed
migration. Orbyn has explicit authority to retire its duplicated installation;
other upstream guidance must remain intact.

149 prior helper tests included the removed installer and consumer synchronizer.
Those obsolete API fixtures are retired rather than retaining an executable
installation. The current suite retains offline reference closure, source notices,
source-integrity failure cases, evaluations, contribution/CI tooling, renderers
and library discovery retirement/recovery. New workspace fixtures cover target
preservation, same-name skills, linked worktrees, external/symlink refusal, ignored
content and CLI behavior. Static/helper results are not live model or host trials.
Historical evaluation protocols and their results remain unchanged; only active
development setup rubrics now describe the nested contract.

No REA engine, provider or runtime upgrade is included. App CI dependencies must
be moved to project-owned paths before a consumer removes its copied skills.
Required notices stay with the code, and app-specific development/operations
facts remain project documentation. This record does not assert merge or main-CI
status; GitHub and the delivery report identify the actual final revisions.
